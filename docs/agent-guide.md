# 图书借阅与空间预约 Agent：启动、操作与验收

主题找书与知识库联动、个人借阅查询和申请归还均已实现。借阅链路为：找书 → 选择书目 → 确认申请 → 待管理员确认借出；归还链路为：我的借阅 → 选择借阅记录 → 确认申请归还 → 待管理员确认归还。入口是 `/assistant` 页面右上角的“图书借阅助手”。模型使用现有本地 DeepSeek 配置，LangGraph 随 FastAPI 运行，不需要单独启动。

空间预约助手已接入：明确填写条件 → 查询空间 → 选择空间 → 确认申请 → 待管理员审核。管理员仍通过原有页面审核借还和预约。管理员审批 Agent、组合任务规划及多 Agent 尚未接入。

## 怎么启动

先确保 MySQL 服务运行，并在 `backend` 安装更新后的依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

数据库与 DeepSeek 配置仍只保存在本地 `backend/.env`。新增配置均有默认值：

```dotenv
# local：进程内调用同一业务工具；mcp：经本地 MCP 服务调用
AGENT_TOOL_TRANSPORT=mcp
AGENT_MCP_URL=http://127.0.0.1:8002/mcp
# 可选；默认 backend/data/agent/checkpoints.sqlite
# AGENT_CHECKPOINT_PATH=D:/Ai-Learning/Project/lab-agent/backend/data/agent/checkpoints.sqlite
```

仓库默认 transport 为 `local`，本次本地验收已设置为 `mcp`。修改配置后重启 FastAPI；改了 MCP 使用的数据库/JWT 配置时也重启 MCP。无需新增模型密钥。

完整系统共五个终端；仅使用借阅助手时启动前三项即可。每项在各自终端保持运行，建议后台工具服务先于 API 和前端启动。

| 服务 | 终端工作目录 | PowerShell 命令 |
| --- | --- | --- |
| Vue | `lab-agent/vue-project` | `npm run dev` |
| FastAPI | `lab-agent/backend` | `.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000` |
| MCP | `lab-agent/backend` | `.\.venv\Scripts\python.exe -m uvicorn app.mcp.library:app --host 127.0.0.1 --port 8002` |
| Chroma（RAG 使用） | `lab-agent/backend` | `.\.venv\Scripts\chroma.exe run --path .\data\chroma --host 127.0.0.1 --port 8001` |
| 索引 worker（文档入库使用） | `lab-agent/backend` | `.\.venv\Scripts\python.exe knowledge_worker.py` |

打开 `http://localhost:5173`。使用 `local` transport 时无需 MCP 终端，借阅助手仍复用相同业务契约。Harness 是按需运行的测试程序，不是常驻服务。开发终端可用 Ctrl+C 停止对应服务；若端口已占用，先确认是否已有该项目服务运行，避免重复启动。

首次启动 API 会创建缺失的 `agent_runs`、`agent_actions` 表，不清空现有业务数据。检查点文件只保存图执行状态；MySQL 中的操作记录和借阅记录才是写入回执的依据。检查点和本地验收数据位于 Git 忽略的 `backend/data/`，其中包含用户查询和书目信息，应按应用私有数据保管。

已有 Agent 数据库需要先停 API 和 MCP，执行本轮增量升级，再启动服务。`create_all` 不会修改旧表。以下命令先预览，再添加 `agent_runs.task_type` 和 `agent_actions.action_type`，旧记录默认归为 `borrow`；不重建表，不删除旧记录，可重复执行。本次本机数据库已完成升级。

```powershell
.\.venv\Scripts\python.exe scripts/upgrade_agent_returns.py
.\.venv\Scripts\python.exe scripts/upgrade_agent_returns.py --apply
```

空间预约新增独立 `agent_reservation_actions` 表，不复用借阅操作表。停 API 和 MCP 后，先预览再执行以下增量升级。旧版 MySQL `reservations` 的备注可能不允许空值且审核说明只有255字；第二个脚本允许这两个字段为空，并将审核说明至少扩至500字，保留原备注类型、较大字段、默认值、注释和全部记录，不重建表。重复执行不再改表。本机已完成两项升级，旧表行数及内容摘要前后一致。

```powershell

.\.venv\Scripts\python.exe scripts/upgrade_space_reservation_schema.py --apply
```

## 用户操作

1. 登录，进入“AI 空间助手”，切换到“图书借阅助手”。
2. 输入书名、作者、ISBN 或主题需求，例如“找多智能体相关的书”“推荐一些历史书”。模型最多调用四轮、执行八次只读工具；根据查询结果给出书目卡片。
3. 核对作者、出版社和 ISBN，点击“选择这本书”。此时只生成确认预览，不创建借阅。
4. 点击“确认提交申请”或“取消本次申请”。确认有效期10分钟；提交时重新检查书目信息、账号状态、实际库存和重复申请。
5. 成功后显示申请编号与“待管理员确认”，通过“我的借阅”查看最新业务状态。申请不占库存，不保证最终借出。

刷新页面后重新选择借阅助手，会从当前浏览器会话保存的任务编号恢复，包括任务类型和待确认内容。任务有效期24小时。浏览器只保存任务编号，不保存 MCP 凭证。借阅申请展示本次申请回执，最新借出进度以“我的借阅”为准；归还任务刷新时会重读当前状态，管理员确认后显示“已归还”。

网络中断时先点“刷新任务状态”。如果执行未结束，可点“继续未完成任务”；即使借阅已提交而响应丢失，恢复后也会读取原回执，不再次创建。取消已提交的申请应去“我的借阅”；确认卡片的取消仅用于尚未提交的操作。

查询或归还时，选择“我的借阅”或“申请归还”，可留空查询文字，也可输入书名、作者、ISBN 或明确状态要求。两者都读取当前登录读者的借阅记录，每页6条；记录显示借阅编号、馆藏条码、借出/到期时间、状态及逾期提示。只有 `borrowed` 可点击申请归还；`return_pending` 明确显示等待管理员确认。空列表与工具故障分别提示。

选择记录只生成确认快照，不改变借阅状态。确认卡片同时绑定书目、借阅记录和副本，信息变化或确认过期需重新查询；下架图书仍允许归还。取消卡片不会取消既有借阅。提交后状态是 `return_pending`，仍占副本并计入借阅数量；交还实体书且管理员确认后才释放库存。重复点击、多个任务或与原页面同时申请不会重复变更归还时间。归还申请提交后，本轮不提供撤回功能。

切换“空间预约助手”后，必须明确填写日期、起止时间、人数和用途，可补充空间/设施需求及备注。界面使用北京时间，至少提前两小时，同次预约不能跨天；模型不得补写或改变这些条件。空间卡片展示位置、类别、容量、登记设施及指定时段的检查结果。维护、容量不足、已有通过的重叠预约或提前量不足时禁用选择，并显示原因；查询不返回其他读者的预约信息。

选择空间只创建10分钟有效的确认预览，确认后创建 `pending` 预约，等待管理员审核。只有 `approved` 预约占用时段，待审核申请不锁定空间；空间当前的 `busy` 状态不代表未来时段不可申请。翻页和刷新重查实际状态，确认时再次校验账号、空间快照和时段。相同读者、空间、日期、起止时间且人数/用途/备注相同的有效预约在 Agent 与原页面间复用；内容不同时提示已有申请。管理员审核时也会重新检查冲突。

空间任务单独保存浏览器会话任务编号，页面刷新可恢复条件、确认卡或回执。重复确认、丢失响应后的恢复不重复创建预约；刷新可显示管理员通过、驳回或原页面取消后的状态。确认卡的“取消本次操作”只取消尚未提交的操作，已提交预约通过“我的预约”按原有提前两小时规则取消。本轮没有 Agent 改期或取消已提交预约功能，也未新增正式开放时段、闭馆日或最长预约时长规则。

## 执行结构

```mermaid
flowchart LR
    Q[显式选择：找书 / 我的借阅 / 申请归还 / 空间预约] --> R[按任务提供只读工具的有界 ReAct]
    R --> S[持久化暂停：选择书目、借阅记录或空间]
    S --> P[生成确认记录]
    P --> C[持久化暂停：确认或取消]
    C --> A[重新校验并幂等执行业务]
    A --> E[返回待管理员确认回执]
```

- `app/agent/tools.py` 定义严格参数、只读工具白名单和安全错误。模型不能传入用户身份，也没有写工具。
- `app/agent/graph.py` 控制查询循环与两个暂停节点，保存工具决策，不保存模型内部推理或云端响应元数据。工具故障与无匹配书目区分显示。
- `app/agent/runtime.py` 验证任务归属，通过数据库租约串行化同一任务的执行，使用本地 SQLite 检查点恢复。单次活跃执行预算60秒，模型调用超时最多20秒；人类等待不占用连接，数据库锁等待另受数据库设置限制。
- `app/agent/actions.py` 将具体书目快照、操作者、确认期限和申请回执绑定。借阅变更与操作完成记录在同一 MySQL 事务中提交；同一读者行锁及唯一约束防止并发重复申请。
- `app/agent/reservation_actions.py` 绑定空间、不可变条件与确认期限，预约写入和操作完成在同一事务内提交。空间服务、原预约页面与 Agent 共用读者/空间锁、实时冲突判断和去重规则。
- `app/agent/mcp_adapter.py` 与 `app/mcp/library.py` 连接相同业务服务。MCP 不包含另一套库存或借阅规则。

MCP 是仅供本项目后端调用的第一方接口，采用 Streamable HTTP。它不是通用第三方 OAuth 登录服务：运行时签发90秒有效的专用凭证，校验签名、签发方、受众及作用域。签名密钥由本地 JWT 密钥进行用途隔离派生，普通 Web 登录 JWT 不可用于 MCP；凭证不进入提示词、检查点或前端。

找书凭证 `catalogue:read` 只允许 `search_books`、`get_book`；个人查询凭证 `loans:read` 只允许 `list_my_loans`、`get_my_loan`，不接受用户身份参数，输出不包含读者账号字段。运行时也按任务限制工具白名单。`submit_borrow_decision`、`submit_return_decision` 各自要求限定操作类型、具体操作 ID 和确认决定的凭证，只有固定执行节点才签发，模型工具列表不包含写工具。MCP 再校验操作所属用户和实时业务规则；归还凭证不能用于借阅。以后接入第三方客户端时，应另行设计标准授权流程。

空间查询凭证 `spaces:read` 只允许 `search_spaces`、`get_space`。`submit_reservation_decision` 需要独立的 `reservation:decision` 凭证，同样绑定用户、操作和布尔确认决定；借阅/归还凭证不能提交预约。模型只能读取，不能调用此写工具。local 与 MCP 返回相同契约，只有实时检查时间可能不同。

当前仍是单 Agent 图编排：前端显式选择 `task_type`，同一有界 ReAct 按类型查询，后续由确定节点选择、确认和执行业务。没有多个模型角色协商，也没有自动跨业务规划；MCP 是工具传输，Harness 是验证程序。

当前 SQLite 检查点方案面向本地单 API 实例，不宣称支持多机部署。执行租约有效期3分钟，进程突然退出后需等租约到期再恢复。并发规模、共享检查点、自动数据保留清理策略属于后续部署工作。

## API

所有接口要求当前登录用户；服务端重新核对任务归属。沿用项目响应格式，须同时检查 HTTP 状态和响应体 `code`。

| 方法与路径 | 参数 | 作用 |
| --- | --- | --- |
| `POST /api/agent/runs` | `request_id`（UUID）、`query`、`task_type`、`conditions` | 幂等创建任务；类型为 `borrow`（默认）、`my_loans`、`return` 或 `reservation`；仅预约要求条件 |
| `GET /api/agent/runs/{run_id}` | 无 | 查看任务进度或回执 |
| `POST /api/agent/runs/{run_id}/select` | `book_id` | 选择本次查询返回的书目 |
| `POST /api/agent/runs/{run_id}/select-loan` | `loan_id` | 选择当前页中本人的借阅中记录 |
| `POST /api/agent/runs/{run_id}/loans-page` | `page` | 使用本次状态/关键词过滤翻页，不调用模型或执行业务写入 |
| `POST /api/agent/runs/{run_id}/select-space` | `space_id` | 选择当前页中指定时段可申请的空间 |
| `POST /api/agent/runs/{run_id}/spaces-page` | `page` | 按本次关键词翻页，重新检查条件，不调用模型 |
| `POST /api/agent/runs/{run_id}/decision` | `action_id`、`confirmed`（布尔） | 确认或取消本次具体操作 |
| `POST /api/agent/runs/{run_id}/retry` | 无 | 恢复未完成执行，不跳过人工暂停 |

API 的 `query` 仍要求非空；前端在个人/空间查询输入留空时发送默认查询文字。同一个 `request_id` 绑定查询、任务类型及预约条件，不能重用为另一任务。默认类型保持旧客户端兼容。`conditions` 包含 `date`（YYYY-MM-DD）、`start`/`end`（HH:MM）、整数 `people`、`purpose` 和可选 `note`；其他任务不接受此字段。模型尝试更改条件时明确报查询故障，不能退回猜测的条件。

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_agent.py
# 可选保存不含凭证的结果，目录需已存在
.\.venv\Scripts\python.exe scripts/evaluate_agent.py --output .\data\agent-harness.json
```

该命令强制使用隔离 SQLite、假模型决策和测试身份，执行70项契约测试，不访问业务数据库或云端模型。覆盖只读约束、非法参数、账号停用、工具预算、工具故障、进程重建后的检查点恢复、人工确认、取消、过期、跨用户访问、书目/借阅/空间快照变化、事务回滚、提交后响应丢失恢复、个人及空间查询分页和实际 MCP 协议调用。`backend/tests/fixtures/agent_returns.json` 固定六种状态的可归还预期；`space_reservations.json` 固定可用、维护、超容量、当前忙碌但未来可约、通过预约冲突、待审核不占用、相邻时段不冲突七种预期，由真实业务流转构造记录并核验。通过率只代表这些确定性场景，不是模型理解准确率。

MySQL 并发测试沿用 [实体图书指南](books-guide.md#自动测试与复验) 的隔离临时库机制，验证重复借阅确认，以及归还同一操作、不同任务和原页面的竞争提交。每个归还场景均检查只保留一条借阅、待确认仍占库存、重试不改时间、管理员确认后释放库存。不要把 SQLite 测试当作 MySQL 锁行为验证。

`tests/test_reservation_mysql.py` 新增四种实际 MySQL 竞争：同一操作、不同任务、Agent 与原页面同时提交，以及管理员通过与新申请竞争。测试预先建立旧事务快照，验证锁定读取、重复申请去重及通过预约不重叠。`tests/test_space_schema_upgrade.py` 在独立临时库构造旧表和长备注，检查预览无写入、升级不截断、允许空值与500字审核说明，以及重复执行。临时库清理有名称校验，不用于清理业务库。

## 主题找书与知识库联动（2026-10-16）

`search_books` 新增 `mode=auto|exact|topic`，默认 auto 在书名、作者、ISBN 有匹配时保留原精确查询，否则进行主题检索。模型遇到明确主题需求使用 topic；这里的“精确”沿用原有字段内关键词匹配，并非只允许全字符串相等。

主题检索融合分类、来源主题标签及知识库召回；知识库复用中文 BM25、当前配置的 BGE-M3 向量、RRF 和可开关的 rerank。Chroma 查询前限定到已上架书目关联的当前已发布、ready 且向量配置一致的文档版本。切片按书目聚合，每本最多展示3条来源；同名不同版次仍独立保留。分页针对本次召回候选，不表示遍历了整个语义相关目录。

卡片展示出版社、出版年份、ISBN、元数据匹配依据、来源摘录及原文预览。推荐理由由服务端从登记元数据生成，不生成适读年龄、章节内容或阅读难度判断。文档版本号不是图书版次；具体图书版次通过 ISBN、出版信息和外部来源版次核对。没有登记馆藏的书仍可查看，借阅选择按钮禁用，后端继续核验实际库存。

库存不是检查点快照：读取或刷新选择任务时重新计算，提交时再次检查。刷新会移除下架书、停用或被替换的来源；若推荐完全依赖已经失效的来源，则移除该推荐。库存不会自动持续推送，读者可点击“刷新任务状态”。

向量故障保留 BM25 和元数据召回；重排故障回到过滤后的融合排序；知识库关闭或不可用时仅返回元数据匹配。界面会明确显示对应降级提示，包括没有候选时的降级状态。普通 RAG 问答仍沿用原有故障策略。单次找书工具的检索预算最多10秒，受 Agent 总预算限制；MCP 与本地传输共用同一服务契约。

更新后重启 API 和 MCP，确保常驻服务加载新工具参数。本次本机 MCP 已重启；没有修改本地密钥或配置文件。
