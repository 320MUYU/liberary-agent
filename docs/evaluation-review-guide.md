# AI 效果审核使用与验收

管理员在“AI 效果审核”（`/admin/evaluation-reviews`）逐题阅读回答和来源，保存草稿或提交人工判断，并查看覆盖率、回答正确率和引用支持率。此功能不调用模型，不自动判断真实答案是否正确。

## 启动与升级

使用项目既有的 Vue、FastAPI 和 MySQL；回答排版使用 `markdown-it`，更新前端后在 `vue-project/` 执行 `npm install`。旧库可先预览，再执行增量建表：

```powershell
cd backend
.venv\Scripts\python.exe scripts/upgrade_evaluation_reviews.py
.venv\Scripts\python.exe scripts/upgrade_evaluation_reviews.py --apply
```

新增 `evaluation_runs` 与 `evaluation_case_reviews` 两张表，保留已有业务数据；重复执行不会重复建表。正常 API 启动也会创建缺失表。更新代码后须重启没有开启 `--reload` 的后端，再启动前端。审核本身不要求启动 Chroma、索引 worker 或 MCP。

## 导入与逐题核对

1. 用管理员账号登录，打开“AI 效果审核”，导入 `evaluate_library.py` 生成的回答报告 JSON，最大 10MB、5000 条回答。审核模板和单独的人工判断 JSON 不属于回答报告。
2. 优先审核修复后回归的 16 条回答，再审核历史验证 60 条和调参 40 条。报告编号固定到回答、标注和来源预览；同一编号重复导入会恢复已有进度。导入的外部 `review` 和 `metrics` 不作为本站人工判断。
3. 依次核对问题、前序问题、实际回答、预期事实与标注证据。标注也可能存在歧义，发现问题应写备注，不能只按关键词命中决定正确。
4. 对照“实际返回的来源摘录”和“完整来源预览”。前者是模型回答携带的摘录；“正文已引用”表示正文出现该编号。完整预览有更多上下文，不能仅凭完整原文中存在某句话，就认定较短的实际引用支持了它。
5. 分别选择“回答是否正确”和“引用是否支持回答”，记录遗漏、适用机构、否定条件或需复核事项。拒答题的引用支持性表示拒答没有借用不当引用；判断依据不足时先保存草稿。
6. “保存草稿”允许判断未填完；“提交审核”要求两项明确的布尔判断。提交人来自当前登录管理员，客户端不能指定他人身份。服务出错的题目不能标为回答正确。

题号须以字母或数字开头，只能包含字母、数字、`.`、`_`、`:`、`-`，最长200字；忽略大小写后也须唯一，以兼容 MySQL 唯一约束和接口寻址。哈希校验用于检测报告内容是否与编号匹配，不是来源签名，也不证明回答正确。

前序区展示报告实际保留的问题；未保存的历史回答不会由页面补造。机器预审重点和四组待确认事项见 [逐题机器预审](rag-machine-pre-review.md)。

## 进度、指标与冲突

- 页面记住当前管理员最近选择的报告和题号；已保存的判断存入 MySQL，刷新后重新载入。未保存输入在离开或切题时提示确认。
- 待审核与草稿不计入正确率；0 条已提交时，正确率和引用支持率为 `null`，页面显示“待审核”。覆盖率分母为本报告全部回答，正确率和支持率分母仅为已提交回答。
- 筛选包含全部、待审核（含草稿）、已审核、人工未通过、自动契约未通过。人工未通过指已提交且任一判断为否；筛选不改变汇总分母。
- 已审核题目再次“保存草稿”会移出人工统计，重新提交后再计入。备注、最近修改人、时间和版本随每次保存更新；当前版本保存最后一次判断，不提供历史版本回放。
- 每次修改携带版本号。两个页面同时保存同一版本时，只有一个成功，另一个收到冲突提示。冲突或网络失败会保留输入；可先复制备注，再“重新载入本题”查看服务器判断并决定如何修改。响应丢失时先重新载入，以确认服务器是否已经保存。

## 回答排版与管理员提醒

聊天中的直接回答、知识回答和审核页共用阅读排版，支持段落、标题、强调、编号、项目符号、引用块、代码和表格。宽表格在回答区域内横向滚动。审核页“原始文本”显示报告保存的完整回答，可核对 Markdown 标记、换行和引用编号；切换视图不修改回答、报告或人工判断。历史纯文本按原文显示；新的普通问答和知识问答提示词要求先给结论、分项说明并保留就近引用。模型实际输出仍需审核。

管理员登录后，左侧“预约审核”“借还审核”“AI 效果审核”旁显示非零待办数；超过99显示 `99+`，悬停可看完整数量。右上铃铛显示合计，展开后分别列出预约待审核、借出待确认、归还待确认和 AI 回答待审核。普通读者保留原有通知入口。

- 预约统计状态为 `pending`；借还分别统计 `pending`、`return_pending`；AI 统计 `pending_human` 和 `draft`，包含所有报告中的未完成题目。
- 点击分类进入对应状态列表；AI 提醒会优先打开仍有未审核题目的报告和题目。同页切换提醒也会更新状态筛选，AI 未保存输入沿用离开确认保护。
- 通过、驳回、确认借出、确认归还、保存人工判断或导入报告成功后重新读取数量；失败不扣减待办。已审核题目重新保存为草稿会重新计入待审。
- 页面可见时每30秒更新，回到窗口或标签页时更新，也可在铃铛中点击“刷新待办”。统计失败会保留上次数量并标记“数量未更新”，暂停周期重试，手动刷新或回到窗口后可恢复。

后端 `GET /api/admin/tasks/summary` 仅允许正常状态的管理员访问，数据库直接聚合计数，不受列表分页影响。无需新增本轮数据库表；已有审核表即可使用。

## 导出与 CLI 兼容

“导出人工判断”生成 `{report_id, cases}`，只含已提交条目，可直接交给既有 CLI；“导出汇总报告”生成带人工指标的完整回答报告。草稿、待审核项和未保存修改均不计入导出结果。

```powershell
cd backend
.venv\Scripts\python.exe scripts/evaluate_library.py review --report data/rag-delegation-acceptance/regression-report.json --reviews <浏览器导出的.reviews.json路径> --output data/rag-delegation-acceptance/manual-review/regression-workbench-reviewed.json
```

输出请使用新文件名，保留首次评测和原有审核工作副本。审核进度依赖数据库备份；导出的人工判断可供 CLI 使用，当前页面不提供人工判断文件回灌。
